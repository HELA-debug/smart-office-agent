# 技能：表格排版（sheet-layout）

## 适用场景

要交一份别人能直接算、能透视、能继续填的表格：台账、明细、汇总、对比、排班、预算、库存。
生成用 `code_run_python` + `xlsx_utils`（`write_grid` / `write_table` / `append_records` /
`group_sum` / `add_total_row`），改既有表先 `backup`。

## 零点一、先分清这张表是「记录表」还是「网格表」

这两类表写法完全不同，用错了就出「内容填错位置」：

| | 长什么样 | 用什么写 |
|---|---|---|
| 记录表 | 一行一条记录，第一行是列名（台账 / 明细 / 汇总 / 名单） | `write_table(headers=..., rows=...)` |
| 网格表 | 行和列**都是标签**（课表：上边是星期、左边是节次；排班：上边是日期、左边是人） | `write_grid(rows=...)` |

**网格表必须先把格子摆满再写。** `write_grid` 收的是一个二维矩阵：每一行等长，
空格子写 `None` 但位置要占住。

```python
rows = [
    ["节次", "时间", "周一", "周二", "周三", "周四", "周五"],
    ["1–2", "8:00–8:45\n8:55–9:40", "语文\n张老师 301", None, None, "数学\n李老师 202", None],
    ["3–4", "10:10–10:55\n11:05–11:50", None, "物理\n王老师 105", None, None, None],
]
write_grid(
    out, rows, sheet="课表", title="2024 秋季课表", preset="课表", merges=["A3:A4"], freeze_cols=2
)
```

**为什么不能按顺序往右填。** 你手上是 OCR 读出来的一串文字，周四没课那一格在文字里
根本没有痕迹；一旦「有内容就往后挤」，周五的课就落到周四、周四的落到周三——整行左移。
2026-11-10 线上就是这样：周五的两节课被填到了周一、周二。**空格子不是省略，是信息。**

一格里的换行用 `\n`（`write_grid` 会开自动换行）；跨行的格用 `merges`（"A3:A4"）。

## 零点二、素材是「截图里的表格」时怎么读

识别结果开头带一句「（以下是表格：N 列 × M 行…）」就说明它已经被还原成网格了：

- **每一行的 `|` 之间是固定的一列**，`—` 是原图里的空格子。按列对齐读，
  不要因为有空格子就跳过——跳过一位，后面整行都错位。
- 同一格的字被折成几行时，会**连着出现好几行、而且在同一列**。按列把它们合成一格，
  不要当成好几条不同的记录。
- 折行的字可能被切断（「移动应用服务器/编/程」），按上下文补齐，别照着断字写进表格。

**产物里不要放「识别原文」。** 那一串流水文字的行列本来就是错位的，贴进去读者只会
盯着它怀疑整份数据。要交代不确定的地方就写「核对说明」：按什么规则复原的、
哪一格还没把握、原文疑似认错的字（如「8:00-3:45」推为 8:45）。核对说明留，
识别原文删。

## 一、先定这张表是干什么的

| 表类型 | 一行是什么 | 要不要合计 | 冻结 |
|---|---|---|---|
| 台账 | 一条记录（一次发生） | 不要（合计没意义） | 首行 + 筛选 |
| 明细 | 一个条目（一次拆解） | 不要 | 首行 |
| 汇总 | 一个分组 | 要 | 首行 |
| 对比 | 一个对象的两套指标 | 不要 | 首行 |
| 排班 / 考勤 | 一个人的一个月 | 考勤要 | 首列（人名） |
| 预算 / 报销 | 一笔支出 | 要 | 首行 + 筛选 |
| 库存 | 一个 SKU | 要 | 首行 + 筛选 |

**一张表只干一件事**。台账里混进「本月合计」行，排序一次就乱；汇总表里塞明细，
透视出来是错的。要两件事就两张表（或两个 sheet），别挤在一张里。

## 二、列怎么定

- **第一列是主键**：序号、编号、订单号。没有主键的表，后期对账对不上。
- **一列一种信息**：「状态」列不要写「已完成（12 个）」，拆成「状态」+「数量」。
- **列名是名词**：日期 / 客户 / 金额 / 负责人 / 状态。不要「列1」「项目2」。
- 列的顺序按「读的人怎么用」排：先识别（编号、名称），再时间，再数值，最后备注。
- 一张表超过 30 列，说明该拆；超过 20 万行，该拆文件。

## 三、数字格式：值存数值，格式管显示

这一步最容易被跳过，也最容易出事：

- **金额存数值 + 货币格式**（`¥#,##0.00`）。存成文本，右键求和是 0。
- **占比存 0.125 + 百分比格式**，显示成 `12.5%`。直接存 12.5 再加 `%` 号，等于 1250%。
- **日期存日期值 + `yyyy-mm-dd`**。存文本，排序按字符串排，10 月会跑到 2 月前面。
- **编号 / 工号 / 手机号一律文本格式**。不设的话 `00123` 变 `123`，`13800001111` 变科学计数。
- 数量、人数用千分位（`#,##0`），别用两位小数——「3.00 个人」看着很怪。

`xlsx_utils.write_table` 会按表头自动推断（看到「金额」给货币、看到「占比」给百分比、
看到「备注」给宽列）。**推断只是兜底**：你明确知道口径时，直接传 `number_formats`。
语义名在 `sheet_lexicon.NUMBER_FORMATS`（金额 / 百分比 / 日期 / 千分位 / 文本…）。

## 四、版式：交给引擎，不要自己拼样式

表格的「长相」是三档预设定的，数值都在 `sheet_lexicon.SHEET_PRESETS`：

| 预设 | 给谁用 | 长相 |
|---|---|---|
| `default` | 台账 / 明细 / 汇总 | 表头浅灰加粗居中、数据区全框线、文本左对齐、数字右对齐、冻结首行 + 筛选 |
| `grid`（也叫「课表」「排班表」） | 课表 / 排班 / 值班表 | 全格居中、自动换行、行高给足、冻结首行首列、无筛选 |
| `compact` | 几百行的核对清单 | 字小行矮 |

**不要自己写 Font / Border / Alignment**。脚本里现场拼样式，做出来跟别的产物不是
一套观感，而且改一版就得改一处。要换观感就换预设，要换数值就改词表。

行高与列宽也不用管：引擎按内容估宽（中文算两格），网格表给上限，避免一格的长课程名
把整列撑到屏幕上放不下。

还有几条是不变的：

- 加粗只给表头和合计行，不要整表加粗（整表加粗等于没有重点）。
- 合计行放最下面并在第一列写「合计」，不要放最上面——排序会把它带走。
- 不用彩色底纹区分状态；颜色多了打印出来都是灰的，等于没区分。
- 合并单元格只用在表头分组或「同一值跨几行」（时段、类别），不要用在数据区中间。

## 五、数据质量

- 空格子写「—」或留空都行，但**同一列要统一**；一半空一半「—」会被当成两类值。
- 同一列不要混单位：金额全是元，或者全是万元，写在表头里（「金额（万元）」）。
- 合并单元格只用在表头分组，不要用在数据区：合并后无法排序、无法透视。
- 交付前按主键去一次重，并核对行数与来源条数对不对得上。

## 六、交付前自检（逐项过）

1. 这张表一行代表什么？说得清吗？（说不清就是结构错了）
2. 有没有合并单元格挡在数据区里？
3. 金额、占比、日期三类的格式对不对？占比是不是存成了 12.5？
4. 编号列有没有被转成数字（前导零丢了）？
5. 表头冻结了吗？筛选加了吗？列宽够不够看清备注？
6. 合计行在位、口径写清了吗（「金额（元）」还是「万元」）？
7. 行数和素材对得上吗？有没有重复行？
8. 别人拿到这张表，能不能直接透视？不能的话缺哪一列？

## 禁止事项

- 不把多张表塞进一个 sheet（「表1」「续表」那种）。
- 不用颜色代替数据（红色表示异常，但要有一列「是否异常」）。
- 不在单元格里写单位（「12 万元」），单位写表头。
- 不改既有表不留备份；不把中间过程表当成交付件。
