# 怎么做

1. 先确认三件事再动笔：源语言和目标语言、使用场景（会议口语、聊天消息、字幕、文档），以及交付形态（只要译文，还是要原文与译文对照）。用户没说清的，按“原文在上、译文在下、逐句对应”的默认格式输出，并在开头一行注明语言方向。

2. 从第一条材料里收集专有名词、缩写、产品名、人名和机构名，列一份不超过十行的术语对照表，每个词固定一种译法。后面所有内容都按这张表来，中途不换译法。用户如果给了术语表，就以用户的为准。

3. 按句子切分内容，一句一译，不合并、不调序、不省略。遇到听不清或有歧义的词，保留原文并在译文后加方括号标注，例如 [原文不清]，不要靠猜测补全。

4. 口语内容先去掉“嗯、那个、就是说”这类填充词再译，但语气和态度必须保留：肯定、迟疑、否定不能译反。数字、时间、金额、比例原样照抄，不做换算，不做四舍五入。

5. 每译完一段，立刻回读一遍，只检查三件事：意思有没有偏、术语有没有统一、有没有漏句。发现问题就在这一段落内改，不要留到最后统一收拾。

6. 收尾时输出一句汇总：本次翻译的语言方向、总段数、标注为待确认的位置有几处。用户如果限定了字数或篇幅，比如“每条不超过三十字”“总共不超过五百字”，就严格按这个限制压缩，删修饰不删信息。

# 注意

- 不要意译到改变立场。说话人用的是可能、也许、大概，就不能译成“会”“一定”。
- 不要把长句拆成好几段再重组，实时场景下顺序错乱比句子生硬更致命。
- 不要自行补全没听清的部分。宁可标出待确认，也不要编一个通顺但错误的意思。
- 不要在专有名词上每次换一种译法，同一场内容里必须前后一致。
- 不要忽略用户给的字数和格式要求，超出限制就先压缩，而不是先解释。
