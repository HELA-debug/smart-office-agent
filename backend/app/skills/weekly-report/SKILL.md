# 技能：周报写作（weekly-report）

> 扩展点 4：技能是"方法论文件"，放入 `app/skills/*/SKILL.md` 即被启动加载，无需改代码。
> frontmatter 声明 name/description/triggers/enabled（B3 支持热加载与启停）。

## 适用场景

用户上传会议记录、进展素材，要求整理成周报（weekly）。

## 成文要求

**首选用 `body` 交整篇 Markdown，骨架按下面这个顺序**（读者只读第一节就知道该干什么）：

1. **一句话结论**：这周做成了什么、还差什么、卡在哪。没有总数就不要谈覆盖率。
2. **进度：做了什么、走到哪一步**：能对照的用表格（事项 / 本周结果 / 口径与待补）；
   只有一条就写成句子。数字带口径（区间、样本、时间）。
3. **需要你拍板的一件事**：只写**一件**。写清影响、建议动作、决策时点；没有就写「本周无需拍板」。
4. **风险与问题**：每条「影响 + 建议动作」，按严重程度排。
5. **下周承诺**：每条都要能验收（交付物是什么）；和上面的风险对得上。

正文到此为止：**不要**再补「来源 / 来源引用 / 关键文件索引」这类小节，也不要补
「来源：…」「依据《…》整理」「代码位置沿用…」这类出处落款（用户 2026-11-09 要求去掉，
11-10 又点名索引节；读周报的人不会去核对是哪个文件的第几段）。

细则：
- 摘要式开篇不超过 200 字，先结论后依据，只写材料里出现过的事实。
- 进展每条一句话、动宾结构、不超过 50 字。
- 关键数据直接引用材料原句，不换算、不推算；材料没给总数就写「材料未提供」，不要算一个比例出来。
- 发给老板的版本可以带「（老板版）」后缀，正文把技术细节压到附注。

## 禁止事项

- 不编造人名、数字、日期与结论。
- 材料未提供的信息统一写"材料未提供"，不要用假设填充，也不要留空让读者猜。
- 没有素材时只交骨架（各节标题 + 一句「待补素材」的说明），不要每节各写一句「素材里没有…」。
- 发送邮件不在能力范围内：只产出文件，由用户自己发。

## 模板

- `template=weekly`：完整周报
- `template=meeting`：会议纪要（议题与讨论 / 结论与待办）
- `template=summary`：文件摘要（要点）
