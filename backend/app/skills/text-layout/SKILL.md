# 技能：纯文本排版（text-layout）

## 适用场景

要交一份 `.txt` 或 Markdown：会议逐字稿、访谈记录、日志、大纲、待办清单、
给系统读的输入文件、贴进聊天窗口的长文。
生成用 `doc_generate_report(format="txt")`，或用 `code_run_python` + `text_utils`
（`read_text` / `txt_wrap` / `heading_tree` / `normalize_markdown` / `md_table`）。

## 一、纯文本只有三样东西能分层

没有字号、没有加粗，能用的只有：**空行、符号、缩进**。所以：

| 手段 | 用法 | 别这么用 |
|---|---|---|
| 空行 | 段与段之间一个空行 | 连续两个以上空行（看着像丢内容） |
| 章节标记 | `【一、进展】` 独占一行 | 用 `======` 画大框、用表情符号当标题 |
| 编号 | 一、／（一）／1. ／（1） | 混着用（「一、」下面直接「3.」） |
| 缩进 | 二级条目空两格（半角两个空格） | 用全角空格（复制出去会乱） |
| 分隔线 | 一行 `-` 或 `=` 铺满 | 半截线、花式线（`~~~`、`***`） |

- 标记从 `text_lexicon.SECTION_MARKS` 取，默认 `【】`：正文很少用【】开句，
  所以它最不容易和内容撞。
- 编号从 `text_lexicon.heading_mark(level)` 取，四级固定：`一、`／`（一）`／`1. `／`（1）`。

## 二、不要给正文硬折行

- **一段一行**：整段写在一行里，折行交给打开它的程序（记事本、WPS、我们的预览都会自己折）。
  按 38 个汉字手动折一次，换台机器换个字号就错位；句子还会被切在「组 / RunContext」
  这种词中间，读起来像断句错误。用户 2026-11-16 明确否掉了硬折行。
- **只有定宽排版才手动折**：ASCII 表格、条形图、要和别的行对齐的清单，用
  `text_utils.txt_wrap(text, width)` 按需要的宽度折，`LINE_WIDTH` 只是这类场合的参考值。
- **日志、逐字稿、命令行也不折**：一行一条，折了就没法按行 grep、没法逐行复制。
- 中文段首**不缩进**：缩进靠空格，改字号就废；纯文本里用空行分段更稳。

## 三、文首三行：标题 / 副标题 / 信息行

预览会把开头这几行排成居中的标题块（大标题最大、副标题次之、信息行跟正文同字号）。
写法对不上，排版就散：

```
实验二　光照自适应调光实验报告
基于 Wokwi 的 ESP32 物联网仿真实验

实验名称：光照自适应调光　　实验方式：Wokwi 在线仿真
姓名：敬一博　　学号：202416320112　　专业：智慧能源　　日期：2026-11-11
```

- 第一行只写文档名，**不要把周次、日期、补充说明塞进括号**（「…调光（2026 年第 47 周，
  工作周报）」）：标题被撑长，会在版心正中折断；这些信息本来就该是副标题或信息行。
- 第二行（可省）是副标题：一句说明、不带句末标点、不超过 24 字。
- 信息行一律「字段：值」，字段之间用**两个全角空格**隔开，能一行放下就别拆成两行。
- 这三行之后空一行，再写第一节。

## 四、几种常见文本的写法

**会议逐字稿 / 访谈**

```
【基本信息】
时间：2026-11-07 14:00
参会：张三、李四

张三：这周把退款率口径改了，从支付时间改成下单时间。
李四：改完差多少？
张三：1.2%，比原来的 1.5% 低，但不是同一批单子，不能直接比。
```

一句一行，说话人顶格 + 全角冒号。**不要润色口语**：逐字稿的价值在于原话。

**日志 / 工单**

```
2026-11-07 14:02  INFO   退款率口径切到下单时间，观察 24h
2026-11-07 15:40  WARN   第三方通道超时 3 次，已自动重试
```

时间打头、定宽对齐、一行一条。不加空行，不折行。

**大纲 / 待办**

```
【本周】
- 退款率口径切换（已完成）
- 第三方通道重试（进行中）
  - 超时阈值待定
```

层级靠缩进，条目靠 `-`，同一个列表只用一种符号。

## 五、Markdown 的几句话

- 标题 `#` 后面**必须有一个空格**，否则一半解析器认不出（`normalize_markdown` 会修）。
- 标题不要跳级：`#` 下面直接 `###` 会丢掉层级。
- 表格必须补分隔行（`|---|---|`），否则渲染成一段竖线。
- 列表项之间不空行；空行会让它变成两个列表。
- 行内代码用反引号，长命令用代码块；代码块里不要塞中文全角引号。

## 六、编码与换行

- 默认 UTF-8（无 BOM）。给 Windows 记事本看、且确定只有中文，才考虑 GBK。
- 换行统一 `\n`；混 `\r\n` 会让某些工具把整份文件读成一行。
- 交付前用 `text_utils.read_text` 读一遍：编码猜错会读到乱码，而且不报错。

## 七、交付前自检（逐项过）

1. 第一行是不是标题？读者打开就能知道这是什么吗？
2. 章节标记是不是统一一种？有没有 `【】` 和 `====` 混用？
3. 编号有没有跳级、有没有从「一、」直接跳到「3.」？
4. 正文是不是**一段一行**（没有按 38 个汉字手动折过）？折过的句子会不会被切在词中间？
5. 日志 / 逐字稿是不是一行一条、没被折行折坏？
6. 有没有全角空格、连续三个以上空行、行尾多余空格？
7. UTF-8 读回来是正常中文吗（不是乱码）？
8. 纯文本里有没有残留 `**加粗**`、`# 标题` 这类 Markdown 记号（该转成标记的就转）？

## 禁止事项

- **正文一律左对齐**：.txt 没有对齐属性，从左边起行是它唯一说得通的形态。
  不要为了「看起来居中」在行首塞空格——换个编辑器、换个字号就歪，
  复制粘贴时还会把空格一起带走。docx 那套「正文两端对齐 + 首行缩进两字符」不适用于 txt。
- **不写索引和出处**：不要「关键文件索引 / 文件索引」这类小节，不要在正文里列
  源码路径清单，也不要「来源：…」「依据《…》整理」「代码位置沿用…」这类落款行
  ——读者用不到（用户 2026-11-09 要求，11-10 又点名索引节）。
- 不用表情符号当层级或项目符号（复制到别的系统会变成方框）。
- 不用制表符对齐（不同环境宽度不同，一复制就散）。
- 不把整段 Word 内容直接粘成 txt 而不删自动编号（会出现「一、一、」）。
- 不把内部口径（生成时间、模型名、run_id）写进正文。
