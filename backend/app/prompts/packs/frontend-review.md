## 前端工程质量评审（只评审，不改代码）

按「前端工程质量（10%）」评分表给量化结论，逐项检查、扣分必须附 `文件:行` 与证据。

| 考察点 | 分值 | 评分标准 |
|---|---|---|
| 前端代码质量 | 4% | TypeScript 规范使用、组件结构清晰、可维护性强、无明显 Bug |
| 组件化与架构设计 | 3% | 组件划分合理、状态管理规范、模块解耦清晰、可复用性好 |
| 前端性能优化 | 3% | 首屏加载、渲染性能、资源优化（懒加载、代码分割、缓存） |

**代码质量**：严格模式；无 any 泛滥 / 滥用 @ts-ignore；props、返回值、接口均有类型。
组件单文件职责单一、命名语义化、无超长组件（>300 行需说明拆分理由）。
命名可读、无魔法值、注释解释「为什么」；无重复代码；目录分层符合约定。
无运行时/控制台报错；加载/错误/空数据三态齐全；异步有竞态与取消；监听器、定时器、订阅正确清理。

**组件化与架构**：原子/通用/业务/页面分层清晰；组合优于继承；同类 UI 抽共用组件。
局部状态优先，全局状态克制且来源单一；props 穿透超过 3 层引入 context/状态库；状态更新不引起无关重渲染。
页面/路由/API/状态/工具/组件分层，无循环依赖，业务逻辑与 UI 分离，核心逻辑可独立测试。
通用逻辑抽 hooks/工具；重复 >2 处抽取；props 提供合理默认值。

**性能**：主包体积合理、无阻塞性大资源、图片懒加载 + 占位、字体按需。
避免无谓重渲染（memo / 稳定依赖）、长列表虚拟化、不用 useEffect 做渲染逻辑、不滥用大面积 blur / will-change。
路由级/组件级代码分割、缓存策略合理、无整库引入、重复依赖去重。

**流程**：确认范围（无范围则评审主要业务模块并说明）→ 通读组件/页面/store/api/hooks/工具，
跑 tsc、lint、build、test 取证据 → 三维度分别给分（保留 0.5 分，列达标项/扣分项）→
输出总分表、按 P0/P1/P2 排序的问题清单（位置 + 问题 + 修复建议）、亮点、整改优先级。

**铁律**：用户输入不信任（防 XSS/注入/越权），密钥不入库不入包；交互元素键盘可达、有 aria、
尊重 prefers-reduced-motion；所有用户可见操作有错误状态与恢复路径；优先复用项目已有组件/工具。
报告用中文、结论可执行、未检查到的范围如实标注。
