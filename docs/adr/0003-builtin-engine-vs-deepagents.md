# ADR 0003：第一版用内置确定性引擎，保留 deepagents 适配位

- 状态：已采纳（D2 修订）
- 日期：2026-10-22
- 决策人：A（后端）/ 发起人
- 影响面：Agent 内核、依赖体积、演示稳定性

## 背景

计划书 4.3 的选型是 `deepagents`（LangGraph 运行时），理由是规划/子智能体/审批/文件系统开箱可用。
但在本项目的执行环境里出现了三个现实约束：

1. **依赖体积与安装时间**：`deepagents + langchain + langgraph` 依赖树大，干净机器安装数分钟且易受网络影响，
   与 DoD「3 分钟内 docker compose 可访问」冲突。
2. **确定性演示**：演示要求 5 分钟脚本每次一致（事件顺序、审批时机、产物内容），
   真实 LLM 的非确定输出会让录屏与 CI 断言不稳定。
3. **可替换性才是本版要验证的东西**：毛胚的核心命题是「接口可换」，而不是「押注某个框架」。

## 决策

第一版主链路使用**内置确定性脚本引擎**（`backend/agent.py` 内按剧本驱动），
同时**保留 deepagents 适配位**：

- `agent.py` 暴露唯一装配入口与事件产出器；引擎实现按 `MODEL_PROVIDER` / `MOCK_MODE` 选择。
- 事件协议、工具注册表、子智能体注册表、审批挂起机制与具体引擎解耦：
  换 deepagents 时只需新增一个 `DeepAgentsEngine` 实现，事件转换层不变。
- `backend/subagents/` 与 `backend/skills/` 保留目录与接口占位；deepagents 的
  planning/subagent/checkpointer 能力在 V1.0 接入，用于替换内置编排。

## 影响与代价

正面：

- 零外部依赖即可端到端演示；事件顺序确定，smoke 用例可断言。
- 审批挂起/恢复、产物登记、审计写入这些**骨架逻辑**与引擎无关，先做扎实。
- 镜像小、启动快，CI 稳定。

负面：

- 内置引擎没有真实规划能力，不能验证「Agent 自主拆解任务」的产品价值；
  这部分风险由真实模式与 V1.0 的 deepagents 接入承担。
- 需要维护一层引擎适配代码（已经存在，V1.0 直接复用）。

## 验证方式

- `MOCK_MODE=true` 下 SSE 事件顺序符合 `docs/events.md`（smoke 用例覆盖）。
- 代码核对：引擎选择在装配层，业务接口与工具实现不出现引擎专有类型。
- 迁移路径：V1.0 新增 `DeepAgentsEngine` 并切换 `MODEL_PROVIDER`，事件层无需改动。
