# 纯文本处理知识库（.txt）

> 项目：office-agent-mvp ｜ 对应工具库：`backend/app/services/text_utils.py`（与 Markdown 共用）
> 依赖：标准库。txt 没有样式、没有结构，所有「看起来像格式」的东西都是约定。

---

## 〇、能力边界

| 能做 | 做法 |
|---|---|
| 编码识别与转码（UTF-8 / GBK / UTF-16） | `read_text`（返回实际编码）/ `write_text(encoding=...)` |
| 换行统一（CRLF/CR → LF） | 读写都做，写回固定 LF |
| 字数统计（含中文口径） | `txt_stats`：字符数 / 去空白 / 中文字符 / 行 / 段 / 英文词 |
| 按显示宽度折行 | `txt_wrap(width=40)`，中文算 2 宽 |
| 体检行尾空格、制表符、超长行 | 读出来自己统计（见下） |
| 转成正式文档 | 先整理成 Markdown → `md_to_docx` / `render_markdown_pdf` |

| 不能做 | 说明 |
|---|---|
| 恢复原始排版 | txt 里没有字号/加粗信息，只能按空行与缩进猜结构 |
| 直接当表格用 | 制表符/空格对齐的「伪表格」不可靠，必须人工确认列规则 |
| 超大文件全文读入 | 数百 MB 日志会撑爆内存，按行流式处理 |

## 一、编码：txt 的第一大坑

Windows 记事本/老系统导出的文本常见编码：

| 编码 | 特征 | 判断 |
|---|---|---|
| `utf-8` | 无 BOM | 首选尝试 |
| `utf-8-sig` | 开头 `EF BB BF` | 读出来会带 `\ufeff`，`read_text` 已剥离 |
| `gb18030` | 中文 Windows 默认 | utf-8 解码失败后尝试 |
| `utf-16` | 开头 `FF FE` / `FE FF` | 先看前两字节，否则 utf-8 解码会「成功但全是乱码」 |

```python
doc = read_text(path)      # {"encoding": "gb18030", ...}
write_text(out, doc["text"], encoding=doc["encoding"])   # 沿用原编码
```

**判断乱码不要靠眼睛**：`txt_stats` 里 `cjk_chars` 与 `chars` 的比例接近 0，而内容明显该有中文时，就是编码选错了。

## 二、结构约定（txt 没有格式，只有约定）

改 txt 前先问清（或从内容推断后说明）：

| 约定 | 常见形态 | 处理建议 |
|---|---|---|
| 段落 | 空行分段 / 每行一段 | 保持原有约定，不要混用 |
| 缩进 | 全角空格两个 / 4 空格 / Tab | 保持原缩进宽度 |
| 标题 | 单独一行、前后空行、`一、`/`1.` 编号 | 不擅自加编号 |
| 列表 | `-`/`•`/`·`/`1)` | 统一成一种符号并说明 |
| 折行 | 硬换行（每行 40 字） | 改动后要重新 `txt_wrap`，否则参差不齐 |
| 分隔 | `====`、`----` | 保留，别当正文删掉 |

## 三、场景库

| 需求 | 做法 |
|---|---|
| 把 txt 纪要排成 Word | 整理成 Markdown（加 `#` 标题、`-` 列表）→ `md_to_docx` |
| 统一折行宽度 | `txt_wrap(text, width=40)`，中文按 2 宽计算 |
| 统计字数（按中文字符） | `txt_stats`，报告里写清口径（chars vs cjk_chars） |
| 清理行尾空格与全角空格 | `re.sub(r"[ \t]+$", "", line, flags=re.M)`，全角空格单独说明 |
| 合并多个 txt | 逐份 `read_text` → 统一编码 → 用空行分隔 → `write_text` |
| 从 txt 里提取编号条目 | 按正则抽 `^\d+[\.、)]`，抽完报「共 N 条，跳过 M 行」 |
| txt 转 csv（伪表格） | 先确认分隔符（Tab/逗号/多空格），再 `csv.writer`；不确定就问 |

## 四、函数表

```python
read_text(path, encoding=None)        # -> {file, encoding, text, chars, lines}
write_text(path, text, encoding="utf-8")   # LF 换行，自动建目录
txt_stats(text)                       # -> {chars, chars_no_space, cjk_chars, lines, paragraphs, words}
txt_wrap(text, width=40)              # 中文 2 宽折行，保留原空行
```

统计口径（写进结论，避免用户误解）：

- `chars`：含标点与空白；
- `chars_no_space`：去空白，接近「字数」；
- `cjk_chars`：仅中文字符；
- `words`：连续英文/数字串数量，中文不算词。

## 五、Agent 提示词

```text
处理 txt 时遵守：
1. 先 read_text 报告编码；gb18030 或 utf-16 要在结论里说明，回写沿用原编码（除非用户要求改 UTF-8）。
2. 需要交付正式文档时，先整理成 Markdown（标题/列表/表格），再 md_to_docx 或 render_markdown_pdf，
   不要把整段 txt 直接塞进 Word。
3. 折行宽度、缩进、列表符号都沿用原文约定；改动后重新 txt_wrap，保持整篇宽度一致。
4. 字数按用户口径报：默认给「字符数 + 中文字符数 + 行数」，说明是否含空白。
5. 「伪表格」先确认分隔规则再解析；无法确认就带着原文片段问用户，不要猜列。
6. 改动前 backup，产物写 $OA_OUTPUT_DIR；原文件只读。
```

## 六、常见坑

1. **记事本另存为 ANSI 后中文全乱**：其实是 GBK；用 `read_text` 读，再按原编码写回。
2. **UTF-16 被当 UTF-8 读**：字符串里出现大量 `\x00` 或 `�`，说明字节序没判断对。
3. **CRLF 与 LF 混用**：`read_text` 已统一，自己处理时要先 `replace("\r\n", "\n")`。
4. **行尾空格导致 diff 噪音**：清理前告知用户，避免「看起来没改」却整篇变动。
5. **全角空格缩进被当普通空格**：`\u3000` 不是 `\x20`，用 `strip()` 会连带删掉，要显式说明。
6. **制表符对齐的表格**：等宽字体下才对齐，Word 里会错位；转文档时改成真表格。
7. **文件末尾没有换行**：`write_text` 会补一个，diff 会显示 `\ No newline at end of file` 消失。
8. **行数统计差 1**：`split("\n")` 对末尾换行会多一个空串，用 `txt_stats` 的口径统一。
9. **超大文件**：> 5 MB 先问是否全文处理，或按行区间分段。

## 七、校验清单

- [ ] 编码正确（无乱码、无 `\ufeff`、无 `\x00`）
- [ ] 换行统一为 LF，段落分隔规则未变
- [ ] 折行宽度一致（如果做过折行）
- [ ] 字数口径已说明，与用户预期一致
- [ ] 原文件未被修改；产物路径在结论里
- [ ] 需要交付文档时，已整理结构再转 docx/pdf，而不是整段灌进去
